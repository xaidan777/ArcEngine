# Диагностика: «в игре из редактора всё серое, но звук и HUD работают»

Дата: 2026-09-21. Повод: жалоба «при старте игры через Editor всё серое, звуки и HUD работают,
нет только картинки».

**Итог: это не регресс от правок многопоточности и не «чёрный экран».** 3D-мир рисуется
полностью (85 мешей, 33–43 активных, кадры идут). Кадр тёмный потому, что **карта
`forest_map` сохранена с ночным светом** и в игре честно применяется: солнце под горизонтом
(`sunElevation = −27.7°`), `sunIntensity = 0.215`, `ambientIntensity = 0.185`. Именно поэтому
«видно только серое»: это ночной рейд с почти погашенным светом, а не сломанный рендер.

---

## 1. Что проверено и как

Репро: сервер редактора (`node _utils/editor/server.mjs --port=8090 --no-open`), затем
Playwright (headless Chromium + SwiftShader) открывает **ровно тот URL, которым играет
редактор** — `MapEditor.play()` (`_utils/editor/map-editor.js:89`) делает
`window.open('/index.html?directPlay=1&fps=1&map=<id>')`.

Состояние сцены в запущенной игре (`forest_map`):

```
hasApp: true, meshes: 85, activeMeshes: 33
terrain: nx=343 ny=343 hMin=-43 hMax=293
lights: HemisphericLight:0.18, DirectionalLight:0.22, SpotLight:10.00, PointLight:10.00, PointLight:0.00
clearColor: [0.56, 0.76, 0.88]   (светло-голубой)
gamePhase: 'raid', jobs: 'workers', pp: 'active'
pageerror / console.error: НЕТ
```

Кадр идёт (frameId растёт), 3D живой. То есть «нет картинки» — это «картинка слишком тёмная»,
а не отсутствие рендера.

## 2. Причина

`assets/levels/forest_map.json` → `lighting`:

```json
{ "timeOfDay": 1.2416, "cycleEnabled": false, "sunEnabled": true,
  "sunAzimuth": 18.62, "sunElevation": -27.75,
  "sunIntensity": 0.215, "sunColor": "#8cade6",
  "ambientIntensity": 0.1846 }
```

Для сравнения, `default_raid` (рабочая светлая карта):

```json
{ "timeOfDay": 6, "cycleEnabled": true, "sunElevation": 90,
  "sunIntensity": 3, "ambientIntensity": 0.42 }
```

Замеры кадра (`near-black` = доля пикселей с max(RGB) < 28):

| Карта | near-black | небо (центр верха) | земля |
|---|---|---|---|
| `forest_map` (из редактора) | **67–70 %** | (0, 0, 0) | (12, 16, 13) |
| `default_raid` (обычная игра) | 19 % | (80, 105, 122) | (50, 55, 54) |

Один и тот же замер при **выключенных мешах** показал светлый `clearColor` (143, 194, 224) —
то есть canvas презентуется, рендер идёт, и «серость» приходит именно от геометрии и света.

## 3. Решающий опыт

Я поднял свет вручную — картинка почти не изменилась, потому что свет **перезаписывается
каждый кадр** (`Game.update` → `updateMapLighting`, `js/Game.js:3177`). Когда я остановил
перезапись (`updateMapLighting = () => {}`, `weatherSystem = null`) и выставил полдень,
`DirectionalLight` стал 3.00 — но кадр остался тёмным (`near-black` 70 % → 62 %).

Тогда я проверил скайбоксы. В сцене **два меша с одинаковым именем `hdrSkyBox`**:

```
hdrSkyBox  visibility: 0  refl: assets/environment/industrial_sunset_02_puresky_2k.hdr
hdrSkyBox  visibility: 1  refl: ""            <- НОЧНОЕ небо, перекрывает дневное
environmentIntensity: 0.05
```

`RaidEnvironment.setupSky()` (`js/RaidEnvironment.js:137–225`) создаёт **два** скайбокса:
дневной `this.sky` и ночной `this.nightSky` (процедурное звёздное небо). Оба получают имя
`hdrSkyBox` от `scene.createDefaultSkybox`, потому что имя меша в него не передаётся.

`syncSky(sunAz, nightFactor, sunEnabled)` (`js/RaidEnvironment.js:227–243`) распределяет
видимость:

* `this.sky.visibility = sunEnabled ? 1 − nightFactor : 0`
* `this.nightSky.visibility = sunEnabled ? nightFactor : 1`

А `nightFactor` считает `Location3D.applyLightingSettings` (`js/Location3D.js:84`):

```js
nightFactor: settings.sunEnabled === false || (settings.sunElevation ?? base.sunEl) < 0 ? 1 : 0
```

У `forest_map` солнце **под горизонтом** (`sunElevation = −27.75 < 0`) → `nightFactor = 1` →
дневной скайбокс гаснет (`visibility = 0`), ночной включается (`visibility = 1`). Небо
становится `#01040a` — почти чёрным.

**Прямое доказательство:** я спрятал только ночной скайбокс, не трогая свет:

```
до:   near-black 70 %  небо (0, 0, 0)
после: near-black 35 %  небо (127, 172, 198)   <- небо вернулось
```

Это и есть вся «серость»: игра рисует ночной рейд, потому что карта так сохранена.

## 4. Почему в редакторе выглядело иначе

Редактор **не применяет свет карты к превью**: `applyLightingSettings`
(`js/Location3D.js:69`) вызывается только из игры (`js/Game.js:3184`).
В `_utils/editor/lab.js` нет ни `applyLighting`, ни `syncSky`, ни чтения `level.lighting` —
превью живёт со светом `World3D.cfg()` по умолчанию (яркий день). Поэтому дизайнер видел
светлую сцену в редакторе и тёмную в игре. Это и есть настоящая проблема UX: **превью не
показывает то, что увидит игрок.**

## 5. Откуда взялся ночной свет

По бэкапам карты видно, что это следствие работы в редакторе, а не старой карты:

```
Map-forest_map-1789972696199.json  tod=0.00  el=-8.0   int=1.350  amb=0.600  cycle=False
Map-forest_map-1789972812348.json  tod=0.00  el=-8.0   int=1.350  amb=0.600  cycle=False
Map-forest_map-1789972915955.json  tod=1.24  el=-27.7  int=0.215  amb=0.185  cycle=False
Map-forest_map-1789973863204.json  tod=1.24  el=-27.7  int=0.215  amb=0.185  cycle=False
```

То есть между двумя сохранениями `sunElevation` уехал с `−8` на `−27.7`, а `sunIntensity` —
с `1.35` на `0.215`. При этом `TimeOfDay` сдвинулся на `1.24`, что соответствует глубокой
ночи. Скорее всего, в панели освещения потянули за слайдеры времени/высоты солнца (или
сработал `timeOfDay`-путь `LightManager`, который пишет `sunElevation` из цикла суток,
`_utils/editor/lighting-panel.js:352`).

## 6. Что делать (по приоритету)

1. **Быстро, чтобы играть прямо сейчас:** открыть карту в редакторе, вкладка Lighting →
   поднять «Высота» солнца выше 0 (например 48°) и «Сила солнца» к 1.0–3.0, выставить
   «Эмбиент» ~0.4–0.6 → Save. Либо открыть `?map=default_raid`.
2. **Настоящее исправление UX (рекомендую):** приучить превью редактора показывать свет
   карты — вызывать `location.applyLightingSettings(level.lighting)` и
   `environment.syncSky(...)` в `_utils/editor/lab.js` при загрузке/правке карты.
   Тогда «в редакторе светло, в игре темно» исчезнет как класс.
3. **Защита от случайной ночи:** в игре считать ночной скайбокс только при
   `nightFactor` выше порога (сейчас любое `sunElevation < 0` мгновенно включает полностью
   чёрное небо `#01040a`, без градации), и/или предупреждать в редакторе при сохранении
   карты с `sunElevation < 0` и `sunIntensity < 0.3` («игрок увидит ночь»).
4. **Косметика, но чинит и отладку:** дать двум скайбоксам разные имена. Сейчас оба —
   `hdrSkyBox`, из-за чего в инспекторе и в скриптах их не различить (я сам на этом
   сначала ошибся).

## 7. Про мои правки многопоточности

К этому симптому они отношения не имеют, и хуже не сделали. Специально проверил: с
**откаченным** знаком норм (как было до моей правки) кадр темнее — 83 % near-black против
70 % с исправленным. То есть E1 (нормы) теперь работает **в плюс**, а не является причиной.

Отдельно: этот случай высветил реальный изъян, который я не заметил в первом разборе, —
инвариант «3D — представление» соблюдён, но **редактор и игра расходятся в освещении**,
и это стоит починить (пункт 2 выше).
