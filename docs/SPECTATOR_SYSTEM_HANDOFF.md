# BlackWater Protocol: Архитектура Режима Наблюдателя и Жизненного Цикла Рейда (Backend Handoff для DeepSeek)

**Дата**: 2026-09-20  
**Назначение**: Техническая спецификация для DeepSeek (Backend-разработчика) по устройству режима наблюдателя (Spectator Mode), авторитетной симуляции гибели игроков, защите от эксплойтов при переподключении и будущим механикам реанимации (Revive) и тактических меток (Pings).  
**Сеттинг**: BlackWater Protocol (оригинальный лор без нарушения авторских прав Embark Studios / ARC Raiders).

---

## 1. Концепция и Авторитетная Архитектура

### 1.1. Единственный источник истины (Single Source of Truth)
1. **Сервер определяет жизнь и смерть**:
   - Значение здоровья (`hp`), щита (`shield`), статус гибели и исход рейда определяются **исключительно на сервере** (`server/simulation.mjs`).
   - Клиент не имеет права локально объявлять игрока погибшим или живым в сетевом рейде; он реагирует на авторитетный снапшот сервера.
2. **Изоляция команд погибшего игрока**:
   - Как только `p.hp <= 0`, сервер полностью игнорирует любые входящие команды перемещения (`forward`, `right`, `jump`), стрельбы (`fire`) и использования способностей от данного клиента (`if (p.hp <= 0) continue;`).
   - Стрельба от мертвого игрока не регистрируется, снаряды не создаются, урон не наносится.
3. **Сохранение присутствия в комнате**:
   - Погибший игрок **не исключается** из комнаты рейда, пока в рейде остаётся хотя бы один живой сокомандник (`alive.length > 0`).
   - Погибший игрок продолжает получать авторитетные снапшоты (`snapshot`) с частотой тиков комнаты (20 Hz), что позволяет клиенту отрисовывать действия живых союзников в реальном времени.

## 2. Жизненный Цикл Оперативника в Рейде (State Machine)

```
       [ ВЫСАДКА / DEPLOY ]
                 │
                 ▼
        ┌─────────────────┐
        │  АКТИВЕН (ALIVE) │ ◄──────────────┐
        └────────┬────────┘                 │ (Будущая механика)
                 │                          │ Реанимация дефибриллятором
                 │ hp <= 0                  │ (Field Revive)
                 ▼                          │
        ┌─────────────────┐                 │
        │  ПОГИБ / НАБЛЮДАТЕЛЬ ─────────────┘
        │   (SPECTATING)  │
        └────────┬────────┘
                 │
                 ├──────────────────────────────┐
                 │ Все союзники погибли         │ Союзники эвакуировались
                 ▼                              ▼
        ┌─────────────────┐            ┌─────────────────┐
        │   ВАЙП СКВАДА   │            │    ЭВАКУАЦИЯ    │
        │   (WIPE / LOSS) │            │ (EXTRACT / WIN) │
        └────────┬────────┘            └────────┬────────┘
                 │                              │
                 └──────────────┬───────────────┘
                                │
                                ▼
                       ┌─────────────────┐
                       │  РАСЧЕТ ИТОГОВ  │
                       │   (SETTLEMENT)  │
                       └─────────────────┘
```

## 3. Протокол и Поведение при Гибели и Наблюдении

### 3.1. Структура Снапшота для Наблюдателя
Сервер передаёт в массиве `players` снапшота полные данные всех участников сквада:
```javascript
{
    id: p.id,
    x: p.x, y: p.y, h: p.h,
    heading: p.heading,
    pitch: p.pitch,           // Угол наклона взгляда сокомандника (для ориентации камеры)
    hp: p.hp,                 // Здоровье
    shield: p.shield,         // Щит
    maxShield: p.maxShield,
    posture: p.posture,       // Стойка: 'stand' | 'crouch' | 'prone'
    lean: p.lean,             // Наклон: -1 (влево), 0, +1 (вправо)
    disconnected: !!p.disconnected
}
```

### 3.2. Клиентский переход в Режим Наблюдателя (`js/OnlineBridge.js`)
1. При получении снапшота, где `me.hp <= 0`:
   - Если в скваде есть живые игроки (`(peer.hp > 0 || !peer.dead) && !peer.disconnected`):
     - Включается флаг `OnlineBridge.spectating = true`.
     - Автоматически выбирается первая живая цель `OnlineBridge.spectateTargetId = alive[0].id`.
   - Если живых союзников не осталось:
     - `OnlineBridge.spectating = false`.
2. Клиент прекращает отправку локальных команд управления и переключается на отправку нейтрального пинга (keepalive):
   ```javascript
   { forward: 0, right: 0, heading: 0, sprint: false, fire: false, pitch: 0, posture: 'stand', lean: 0 }
   ```
   Это гарантирует, что сервер не расценит наблюдателя как отключившегося по таймауту (`p.disconnected`).

### 3.3. Авто-переключение при гибели наблюдаемого союзника
Если текущий наблюдаемый союзник погибает в бою:
- Сервер присылает снапшот с `target.hp <= 0`.
- Клиентский метод `getSpectatedPeer()` и обработчик `applyPeers` автоматически переключают цель наблюдения на следующего выжившего союзника (`cycleSpectateTarget(1)`).

## 4. Защита от Эксплойтов при Переподключении (Reconnection)

> [!CAUTION]
> **Уязвимость "Revive on Reconnect" закрыта**:
> Ранее при перезагрузке страницы или переподключении игрока клиент мог повторно инициализировать локальный объект с `hp = 100`, однако сервер помнит истинное состояние сессии:
> - В `server/rooms.mjs` и `server/simulation.mjs` статус игрока и его `hp` привязаны к `playerId` / токену сессии.
> - При повторном входе через WebSocket (`auth` / `reconnect`) или HTTP-поллинг сервер возвращает объект игрока с `hp: 0`.
> - Клиент `OnlineBridge.js` мгновенно распознает `me.hp <= 0` и сразу переводит игрока в Режим Наблюдателя, не позволяя двигаться или стрелять.

## 5. Задачи для DeepSeek (План Расширения Серверной Части)

Для дальнейшего развития тактической глубины сетевого режима BlackWater Protocol Дипсику предлагается реализовать следующие механики:

### 5.1. Механика Полевой Реанимации (Field Revive)
В оригинальных тактических шутерах (ARC Raiders, Apex Legends) павший боец сначала переходит в состояние нокаута (Downed), либо его жетон/ядро можно воскресить на специальном маяке.
**Предлагаемый контракт для DeepSeek**:
1. **Состояние Нокаута (Downed State)**:
   - При падении HP до 0 игрок переходит в `downed: true`, `downedTimer: 30.0` (секунд до окончательной гибели).
   - В нокауте игрок может только медленно ползти (`speed: 40`).
2. **Действие реанимации (`revive`)**:
   - Живой союзник подходит к павшему на расстояние $\le 60$ px и удерживает клавишу взаимодействия (отправляет действие `action: 'startRevive', targetId: '...'`).
   - Если союзник непрерывно удерживает реанимацию в течение 4 секунд (без получения урона):
     - Сервер переводит цель в `hp: 30`, `downed: false`.
     - Сервер рассылает событие `{ type: 'playerRevived', targetId, reviverId }`.
3. **Станция Реанимации (Beacon Revive)**:
   - Если боец окончательно погиб (`downedTimer <= 0`), сокомандник может забрать его жетон допуска (`Clearance Token`) с тела и отнести к стационарному терминалу реанимации на карте.

### 5.2. Тактические Метки Наблюдателя (Spectator Pings)
Чтобы погибшие игроки не скучали, они должны помогать скваду как штурманы/корректировщики:
1. Клиент наблюдателя при клике колёсиком мыши (СКМ) отправляет:
   ```javascript
   { action: 'ping', x: targetX, y: targetY, h: targetH, type: 'danger' | 'move' | 'loot' }
   ```
2. Сервер валидирует координаты и рассылает событие `ping` всем участникам сквада.
3. Живые союзники видят на своём тактическом компасе и в 3D-мире метку с позывным наблюдателя: `[МЕТКА: RAIDER_01 // ОПАСНОСТЬ]`.

### 5.3. Голосовой и Текстовый Канал Сквада (Squad Comms)
- Разделение чата на общий и сквадовый.
- Погибшие игроки сохраняют доступ к радиоканалу сквада для передачи разведданных выжившим бойцам.
